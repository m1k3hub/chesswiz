Development roadmap

Working format strategy

Chesswiz should treat .sci as the primary working format for large databases and repeated analysis. Other formats should mainly be treated as import or source formats. The user interface should make conversion to .sci easy and should recommend this path before slow workflows.

Features for next releases

  • Download/upload/update/load databases via the internet
  • Supporting attachments of documents to a database. The main reason is that some external databases have attached documents.
  • Search functions: search by header, position search, etc. based on CQL
  • Filter functions: game filter, player filter
  • Flexible window layout
  • Support of variant Bughouse
  • Support of variants in opening tree
  • Document generation:: LaTeX export
  • Windows support
  • Input of moves with keyboard
  • Board photo
  • Chesswiz website (downloads, documentation, news)
  • The .sci format: a written specification of the format as it is, and faster, more robust algorithms for reading, writing and searching it

Recently completed (HTML & multimedia)

  • Native HTML stack: safe intake (sanitizer), built-in report viewer on the bundled HTML widget, and standalone HTML publishing (export) with tag tables, variations, comments, and inline-SVG diagrams. HTML files can be opened directly (File > Open > HTML documents) - all foreign markup is sanitized before display.
  • External multimedia: .cbm manifests, the media panel (grouped pictures/audio/video), embedded playback, and board-synced lessons (Chess Media System semantics).
  • Interactive media lessons: .cms indexes and position-keyed clips, driven by the board.
  • Chess 960: move-exact decoding of real .cbh/.cbv archives (Chess960 lookup table).

Multi-game book export (PDF and LaTeX)

Export a whole database or a filtered game list to PDF or LaTeX from the export dialog. LaTeX output is one document with a table of contents and a section for each game's players, event and date. Compile it twice with pdflatex to populate the contents (the skak and KOMA-Script packages are required). Single-game TeX export is also enabled: the native writer reads the selected database game directly. Exports of more than 500 games ask for confirmation before writing a PDF or TeX book.
