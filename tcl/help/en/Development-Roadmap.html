Development roadmap

Working format strategy

Chesswiz should treat .sci as the primary working format for large databases and repeated analysis. Other formats should mainly be treated as import or source formats. The user interface should make conversion to .sci easy and should recommend this path before slow workflows.

Features for next releases

  • Download/upload/update/load databases via the internet
  • Supporting attachments of documents to a database. The main reason is that Chessbase databases have attached documents.
  • Search functions: search by header, position search, etc. based on CQL
  • Filter functions: game filter, player filter
  • Flexible window layout
  • Support of variant Bughouse
  • Support of variants in opening tree
  • Document generation:: LaTeX export
  • Windows support
  • Input of moves with keyboard
  • Board photo
  • Chesswiz website (downloads, documentation, news)

Recently completed (HTML & ChessBase media)

  • Native HTML stack: safe intake (sanitizer), built-in report viewer on the bundled HTML widget, and standalone HTML publishing (export) with tag tables, variations, comments, and inline-SVG diagrams. HTML files can be opened directly (File > Open > HTML documents) - all foreign markup is sanitized before display.
  • ChessBase media: .cbm manifests, the media panel (grouped pictures/audio/video), embedded playback, and board-synced lessons (Chess Media System semantics).
  • Interactive ChessBase lessons: .cms indexes and position-keyed clips, driven by the board.
  • Chess 960: move-exact decoding of real .cbh/.cbv archives (Chess960 lookup table).

Known limitation: single-game PDF/TeX export

The export dialog's single-game PDF/TeX path is gated because the underlying print path dereferences an uninitialized game entry when called (crash reproduced in a minimal harness; the PGN export of the same loaded game works, so the bug is specific to the print-game game-window accessor). Single-game HTML export is unaffected and fully functional. Fixing this requires a game-window lifecycle fix, tracked together with the .cbm in-app linkage work.

HTML & media: next steps

  • Done: ChessBase rich-text comments are rendered through the sanitizer in HTML exports (no more plain-text flattening).

  • Done: the .cms x/y selectors are decoded: they are file-major 0-based from/to squares of the lesson's key move (verified 109/109 legal against python-chess); hotspot geometry is available to tooling.
  • In progress: the .cbm linkage region is a property store keyed by moves (German SAN tokens); the value layout and per-game attribution remain open.
