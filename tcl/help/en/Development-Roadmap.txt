TITLE Development roadmap

<h2>Working format strategy</h2>

<p>
Scidb should treat <abbr>.sci</abbr> as the primary working format for large databases and repeated analysis. Other formats should mainly be treated as import or source formats. The user interface should make conversion to <abbr>.sci</abbr> easy and should recommend this path before slow workflows.
</p>

<h2>Features for next releases</h2>

<ul>
  <li>Download/upload/update/load databases via the internet</li>
  <li>Supporting attachments of documents to a database. The main reason
      is that Chessbase databases have attached documents.</li>
  <li>Search functions: search by header, position search, etc. based on CQL</li>
  <li>Filter functions: game filter, player filter</li>
  <li>Flexible window layout</li>
  <li>Support of variant Bughouse</li>
  <li>Support of variants in opening tree</li>
  <li>Document generation:: LaTeX export</li>
  <li>Windows support</li>
  <li>Input of moves with keyboard</li>
  <li>Board photo</li>
</ul>

<h2>Recently completed (HTML &amp; ChessBase media)</h2>

<ul>
  <li>Native HTML stack: safe intake (sanitizer), built-in report viewer on
      the bundled HTML widget, and standalone HTML publishing (export) with
      tag tables, variations, comments, and inline-SVG diagrams. HTML files
      can be opened directly (File &gt; Open &gt; HTML documents) - all
      foreign markup is sanitized before display.</li>
  <li>ChessBase media: <abbr>.cbm</abbr> manifests, the media panel (grouped
      pictures/audio/video), embedded playback, and board-synced lessons
      (Chess Media System semantics).</li>
  <li>Interactive ChessBase lessons: <abbr>.cms</abbr> indexes and
      position-keyed clips, driven by the board.</li>
  <li>Chess 960: move-exact decoding of real <abbr>.cbh</abbr>/<abbr>.cbv</abbr>
      archives (Chess960 lookup table).</li>
</ul>

<h2>Features for the far future</h2>

<ul>

  <li>Document generation: PDF export</li>
  <li>Dialog for spell checking player names</li>
  <li>Tip of the Day window</li>
  <li>Generating opening reports</li>
  <li>Usage of end-game tables</li>
  <li>3D chessboard</li>
</ul>

<h2>HTML &amp; media: next steps</h2>

<ul>
  <li>Cross-database links in reports (<abbr>scidb-open:</abbr>): opening
      the linked magazine section.</li>
  <li>ChessBase rich-text comments rendered through the sanitizer instead
      of plain text in HTML exports.</li>
  <li>Decoding the <abbr>.cbm</abbr> bag-to-game linkage (per-game media
      attribution straight from the manifest).</li>
  <li>Decoding the <abbr>.cms</abbr> x/y selectors (hotspot geometry).</li>
  <li>Persisting decoded lesson timelines (<abbr>.cms</abbr> BoardSync
      section) so the decode runs once per media file.</li>
</ul>
